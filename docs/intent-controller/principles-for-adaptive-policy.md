# Principles for Adaptive Policy

Authors: [Michael Taufen](mailto:mtaufen@google.com), [Justin Santa Barbara](mailto:justinsb@google.com)  

May 26, 2026

**Some policies must be generated:** Agents are dynamic. This is a strength and a weakness. A strength, because they can *handle* variance. A weakness, because they *have* variance. Therefore, agents need to be protected by rules-based, deterministic policy. No set of rules can cover every situation, therefore rules-based policy needs to be generated to enforce least-privilege based on the situation. Policy enforces bounds on agent behavior, keeping them in a safer range. Some policies can and should still be written and reviewed by humans, when the required bounds on agent behavior are relatively predictable.

**Policies must be derived from trust:** Security is rooted in trust, and insecurity is rooted in absence of trust. Agents are fundamentally vulnerable to prompt injection, despite myriad mitigations. Therefore, policy must be generated from high-trust context *before* encountering untrusted content. For example, the system prompt or skill that describes the agent's job is generally trusted, whereas content the agent encounters while performing that job is less likely to be safe.

**Mathematical perspective:** Despite their complex behavior, agents are still just functions. Functions have domain and range. A policy generator is a function *ft* with trusted domain that outputs a function *fp*, called a *policy*, that clamps the range of another function *fu* with untrusted domain. Given untrusted input, where *fu*'s output could be dangerous, *fp ∘ fu* can be safer, conditional on a "good" policy being generated.

**Modularity:** Agentic systems should be composed of "modules" that each perform a specific job, where the job is clear in the system prompt. It is impossible to correctly generate narrow policy for broad agents that lack constraints in their instructions. The module breakdown may be generated by humans or AI systems, however we'd like to see good statistical evidence of the latter doing a good job before letting go of the steering wheel.

**Layers:** Requirements (and the derived policies) can be composed in layers, with each layer enforcing a constraint appropriate to the scope or level of detail of the layer. For example, upper layers may specify high level goals like "ensure no one failure can cause an outage" or "there must always be two layers of defense between untrusted tenants," which are translated into lower layers that specify an allowable domain of variables, values, operations, and combinations thereof. At each layer, a policy generator can then translate the requirement into appropriate deterministic policy controls (a broad "no external network access" policy translates to a default deny firewall rule, and a narrow "only these two workloads should communicate on this port" translates to a more nuanced firewall rule). **Automatic problem decomposition:** Agents already do problem breakdown and automatic sub-agent generation, they should be able to apply policy generation as a step in this process. For example, the high level agents in gke-labs/kube-agents could break problems down into sub-agents, and apply appropriate policy prior to executing them. Care must be taken to ensure that problem decomposition happens *before* encountering untrusted content, which may be difficult if the interesting problems are only evident in content that can't be trusted.

**We need better prompt injection mitigations:** At this time, almost all prompt injection filters seem possible to bypass. We need fundamentally better mechanisms for prompt injection filtering, or for making agents resistant to injection in the first place. Without this capability, it is unsafe to allow systems to adjust policies based on live feedback from the environment, which limits the ability for the system to adapt. Adaptation is a key benefit of systems with persistent memory, like OpenClaw or Hermes Agent. As agents and memory implementations improve, the opportunity cost of preventing policy adaptation will increase.

**Memories and Policy:** Even though they may contain extremely relevant information for setting the correct policy, persistent memories based on potentially untrusted content are unsafe to use during policy generation, without some additional mitigation. 

**Judgement:** Ultimately, useful systems will need to make judgement calls on whether enough layers of defense exist between useful, but potentially untrusted, content and agents making decisions, conditioned on the power of those agents. Evidence on how well the system defends against attacks is paramount.
